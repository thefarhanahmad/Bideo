## 4. Server and security
- [ ] **Change the server root password** — run `passwd` on the server (it was shared in a chat)
- [ ] **Upgrade the VPS**: 4+ CPU cores (dedicated if possible) and more storage
- [ ] **Free disk space** (~2.9 GB free, 98% full): move the 82 GB of old videos in
      `backend/uploads/videos` to Cloudflare R2, or buy more storage
- [ ] **Password reset is not secure yet**: the code is shown in the app and `1234` still works.
      Anyone can reset **any app user's** password with just their phone number.
      Later: send the code by SMS (MSG91 / Twilio / Firebase), stop returning it to the app,
      remove `1234`, add rate limits, use 6 digits
- [x] **Admin login secured (done 21 Oct, live)**: admin signs in only on bideo.in/login with
      **email + password** (`admin12@bideo3.com`). Admin tokens use their own `ADMIN_JWT_SECRET`
      (in `backend/.env` — keep it there on every deploy). Admin accounts are refused by the app
      login, forgot/reset password and Google login. `irfan_technical` is now a normal creator account.
- [ ] **Change the admin password** to a new strong one — the current one is written in
      `credentials.txt` and was in the old `backend/scripts/updateAdmin.js` (removed), so it stays in git history
- [ ] **App login secret is still the default `supersecretkey`** (`JWT_SECRET` in `backend/.env`):
      anyone can fake a login as **any app user**. Fix without logging anyone out: new secret for
      new logins, accept the old one for 7 days (tokens expire after 7 days), then remove it
- [ ] **App "Login with Google" doesn't check with Google**: the server trusts the email the
      app sends. Fix with the next app release (app sends Google's ID token, server verifies it)
